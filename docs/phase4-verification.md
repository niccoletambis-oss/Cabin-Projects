The security suite covers token hashing/expiry/reissue/single-use concurrency, credential binding, session revocation, login lockout/expiry, shared PostgreSQL throttling, private-parent authorization, image decoding/metadata removal, executable/traversal/size/PDF rejection, owner archive/legal holds, actual streamed form limits, no sensitive monitoring content, runtime HSTS, production seed guard, environment validation and app/Prisma TLS configuration.

Two real issues found during verification were fixed: invalid PNG test fixtures were replaced with decodable images, and `Referrer-Policy: no-referrer` produced `Origin: null` on native Chromium form POSTs. `strict-origin` prevents path/query leakage and preserves normal submissions while null/cross-origin requests remain rejected. Standalone packaging was adjusted to prepare static/public assets and exclude traced environment files. Prisma CLI testing also showed that libpq’s `sslmode=verify-full` alone did not reject a non-TLS server; production CLI configuration now explicitly forces its supported `sslmode=require&sslaccept=strict` and maps the CA file. Application and backup TLS remain independently verified.

The working API authorization boundary remains unchanged: the page proxy still excludes `/api`; each API handler retains its own authentication/role/origin rules. A response-only wrapper adds runtime headers and safe outage responses, including HSTS in production. An attempted broad proxy-routing change was rejected by automatic approval review and was not applied; no approval or exception is needed for the implemented response-header approach.

## Warnings and deployment gates

- Playwright reports the harmless inherited `NO_COLOR`/`FORCE_COLOR` conflict. It does not affect test results. Expected injected failure tests emit sanitized structured error events.
- Real production S3/SMTP credentials, domain, TLS ingress, backup scheduler, retention policy and monitoring collector are intentionally not provisioned. Test actual private bucket permissions/versioning/anonymous denial and SMTP delivery before cutover.
- Local MinIO container acquisition was unavailable from the attempted registries. The official SDK’s local HTTP contract and failure paths are verified; this does not certify a real cloud bucket’s IAM/KMS/replication configuration.
- MFA activation, durable email/monitoring queues, antivirus/full PDF CDR, large-database streaming backup enhancements, formal personal-data anonymization and immutable external audit replication remain deferred. See the operations guide for limitations and recovery responsibilities.
- The production Docker recipe is prepared; the verified production artifact here is the Node standalone build. The image itself and real infrastructure require staging acceptance before deployment.
- No environment draft/network policy was changed or published. Existing Prisma/Playwright/package-manager allowances were sufficient. Provider-specific outbound network/SMTP access may need approval once real services are selected.

Ready for final production deployment preparation, subject to these explicit infrastructure acceptance gates. This is not a declaration that an unconfigured instance is ready for live guests.
